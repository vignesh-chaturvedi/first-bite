Fixed security finding

Critical review priority · Browser defense in depth. Pages previously had referrer/frame/anti-sniffing protections but no enforced Content Security Policy. No working XSS exploit was found or claimed. Add a per-request policy, replace any caller-provided nonce and render dynamically so Next's scripts carry the trusted nonce. Keep HTML uncached so the nonce is not reused.

const { nonce, policy } = createContentSecurityPolicy(isDevelopment);
headers.set('x-nonce', nonce);
headers.set('Content-Security-Policy', policy);
response.headers.set('Content-Security-Policy', policy);
response.headers.set('Cache-Control', 'private, no-store');

// Root layout: render against this request's nonce.
await connection();

The production policy excludes unsafe-inline/unsafe-eval for scripts. Non-asset routes include APIs, prefetches and ordinary missing pages; attacker-chosen prefetch headers and asset-like prefixes cannot skip protection. Development-only allowances support HMR and debugging.

Existing safeguards retained

  • Exact configured Origin, strict JSON schemas, streamed body ceiling and timeout; HttpOnly/SameSite capability cookies and wallet binding.
  • Global-first PostgreSQL rate buckets and fixed public/log error fields. Proxy IP trust requires an overwriting ingress.
  • Distinct S/A/U, full legacy-message comparison, canonical PDAs, immutable message signatures and fixed recovery destination.
  • Authorization serialized with pause and gated by fresh operational evidence; persist before send; retries reuse committed bytes; finality and receipt evidence precede settlement.
  • Authenticated encrypted envelopes; cleanup only when safe; uncertain signed attempts retain their reservations and recovery material.
