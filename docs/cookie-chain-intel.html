The short version

Deploy a program that uses a primitive nobody has used, and file the pull request almost nobody has found.

Cookie Chain ships with compressed NFTs, SPL Governance, and Candy Machine already deployed at genesis. Every one of them has zero accounts on the chain right now. Meanwhile there is no oracle, no lending market, no faucet, and the WebSocket endpoint printed in the official docs serves the wrong TLS certificate.

Separately: the sponsor keeps a public submissions repository containing the real review criteria. Five of the forty-seven entrants have opened a pull request against it. That is the cheapest edge on this page, and it takes about twenty minutes.

Edge 02 · technical

The documented WebSocket is broken

wss.cookiescan.io answers with a TLS certificate issued for bakedbazaar.art and a 301 redirect, so no browser will connect. Every entrant who read the docs is polling. The undocumented upgrade on the RPC host returns 101 Switching Protocols and works.

Works: wss://rpc.cookiescan.io → HTTP 101

The plays

Five builds, ranked

Ranked by sponsor need multiplied by novelty, then discounted for what is genuinely finishable in twelve days by one person. Each includes the honest failure mode.

01

Zero-COOK onboarding

A new user connects Nightly, holds no COOK, and completes a real Cookie Chain transaction anyway — because your relayer pays the fee. They walk away with a compressed NFT proving they were there, minted on a primitive the chain has never used.

Mechanism
Fee-payer separation. Your service partially signs as the transaction fee payer, the user signs as authority. Standard SVM, no new trust model. Rate-limit per wallet, cap the spend, and publish the policy.
Why it wins
It fixes the exact problem ten entrants complained about in the sponsor's own comment thread, and it is the only entry whose demo works for a viewer with an empty wallet. Ship the fee-payer SDK too and every other cApp can adopt it.
First claim
First compressed NFT ever minted on Cookie Chain. Verifiable, and free marketing for the sponsor.
Risk
You are funding strangers' gas. Fees are 0.000005 COOK, so the real exposure is the rent for new accounts. Cap it, and drain-proof the relayer by refusing any instruction you did not build.
Novelty Very high Sponsor pull Very high Effort 5–7 days Demo Excellent
02

The oracle nobody built

A minimal push oracle: an Anchor program holding signed price accounts, a permissionless crank that publishes a time-weighted COOK price derived from Cookiebox pool reserves, and a read SDK any program can call.

Mechanism
Multi-publisher accounts with a documented trust model and staleness bounds. Do not pretend it is Pyth. Ship it as v0, aggregate a median, and make the failure behaviour explicit.
Why it wins
It is the single blocking dependency for lending, perps, and prediction markets on this chain. One build unlocks an entire category, which is precisely what an ecosystem grant vault exists to fund.
Proof it is missing
Pyth, the Pyth receiver, and Switchboard on-demand all return null on this RPC. Verified.
Risk
Thin liquidity makes any pool-derived price manipulable. Say so in the README and bound the confidence interval. A judge will respect honesty here more than a fake precision claim.
Novelty Very high Sponsor pull High Effort 6–8 days Demo Weak alone
03

Real-time gateway and webhooks

A hosted subscription layer over the RPC: account, log, and slot subscriptions that actually connect, plus webhook delivery so other builders can react to on-chain events without running infrastructure. Cookie Chain has no equivalent of Helius.

Mechanism
Proxy the working WebSocket upgrade on the RPC host, add filtering, replay, and HTTP delivery. Ship a five-line client.
Why it wins
You found and fixed a broken documented endpoint. Report the certificate bug to the sponsor before you submit — that alone makes you the person who read everything, and the fix becomes your product's origin story.
Bonus
Every polling dashboard in the field becomes a potential user, and you can show a live latency comparison against polling in the X thread.
Risk
It reads as infrastructure, not an app. The brief says "web application", so you must ship a real UI on top of it, not just an endpoint.
Novelty High Sponsor pull High Effort 4–6 days Demo Good
04

The first realm

SPL Governance is deployed with zero realms. Stand up the first one — a COOK-weighted realm with a working proposal and voting interface, pointed at a real decision such as how the Cookie Jar spends its next allocation.

Why it wins
The chain's entire identity is "community-owned and community-operated" and it currently has no on-chain governance at all. This is the gap between the marketing and the chain state, and closing it is flattering rather than critical.
Integration
Wire it to the existing Squads v4 community multisig so proposals produce executable transactions instead of a poll.
Risk
SPL Governance is fiddly to drive from a fresh frontend and the realm needs real participants to look alive. Seed it with a genuine proposal and get people voting before you record the demo.
Novelty High Sponsor pull High Effort 5–7 days Demo Good
05

Finish the sponsor's launchpad

The cookie-mcp server registers deploy_token and claim_creator_fees but both return a coming-soon notice. Implement them against the CookieBox bonding curve program, which is already deployed and already has forty-seven curves on it.

Why it wins
You are contributing to the sponsor's own repository and closing a gap they documented themselves. Pair it with a web app so an agent and a human can launch the same token two ways.
Risk
The lowest-control play on this list. They said launchpad support is migrating to MomoSwap, so ask in Telegram before you build or you may duplicate work already underway. If they say yes, it is a near-certain win.
Novelty Medium Sponsor pull Very high Effort 4–6 days Demo Good

If you want one recommendation: build play 01 and fold play 03 into it. Sponsored onboarding is the demo, live subscriptions make the confirmation feedback instant instead of polled, and the compressed-NFT receipt gives you a first-on-chain claim. It satisfies every pass/fail requirement naturally and it is the only combination on this page where the demo works for a viewer who owns nothing.

Mechanics that decide the outcome

Filled squares are pass/fail against the sponsor's written criteria. Hollow squares are scoring differentiators.

Non-negotiable

  • Nightly wallet connection, working
  • Deployed at a public URL that loads
  • Public repo, commits dated in the hackathon window
  • Real transactions with confirmation and error states
  • Connected address visible in the UI
  • README with setup instructions

Differentiators

  • Pull request to the submissions repo with logo and screenshots
  • A deployed on-chain program, not just RPC reads
  • A primitive with zero prior usage on the chain
  • Sixty-second screen recording, no narration needed
  • Cookiebox, DAS, or cookie-mcp integration
  • Comment on the listing early with your specific plan
  • Report the WebSocket certificate bug to the team

Disqualifiers seen in the field

  • Repo only, no live deployment
  • A keypair committed to the repository
  • Read-only app that sends no transaction
  • Building against Metaplex Core, which is absent
  • Assuming a price oracle exists
  • A design that needs meaningful liquidity
